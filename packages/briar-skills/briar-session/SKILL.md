# briar-session — kimi-code 会话查询

帮用户找回遗忘的历史会话。kimi-code 的会话按工作目录分组存放在 `$HOME/.kimi-code/sessions/`，本 skill 按时间窗口扫描，返回可恢复的会话清单。

## 触发场景

- 用户说"帮我找下周五下午的会话"、"之前那个会话在哪个目录"、"找回某次聊天记录"
- 用户记得大概时间和聊的内容，但忘了会话 ID / 工作目录

## 工作流

### Step 1 — 确定时间范围

用户必须给出**大概时间范围**（如"周五下午 5 点到 6 点"、"昨天上午"）。如果用户没给，先问清楚再继续。

把自然语言时间换算成具体的本地日期时间（注意用 `date` 确认"今天/周五"对应的实际日期，不要凭记忆猜）。

### Step 2 — 执行查询

```bash
python3 kimi-session-find.py --from "2026-07-31 17:00" --to "2026-07-31 18:00"
```

可选参数：

```bash
--keyword 导购      # 按主题关键词过滤
--all               # 不限制窗口，列出全部会话（配合 --keyword 使用）
```

脚本会扫描 `$HOME/.kimi-code/sessions/` 下所有会话，命中条件为「会话活跃区间与给定窗口有重叠」，输出每个会话的：创建时间、最后活跃时间、主题（title）、工作目录、会话 ID。

### Step 3 — 汇报结果

以表格形式返回给用户，包含：时间、主题、目录、会话 ID（短 ID 即可），并附上恢复方式：

```bash
cd <工作目录> && kimi -S <会话ID>   # 恢复指定会话
cd <工作目录> && kimi -S            # 交互式选择
```

如果结果太多（>10 条），建议用户加关键词缩小范围；如果没有结果，主动扩大时间窗口再查一次（比如前后各放宽 1 小时）。

## 关键约定

- **只读操作**，绝不修改/删除 `~/.kimi-code/sessions/` 下的任何文件
- 时间参数一律用**本地时间**（state.json 内的 createdAt/updatedAt 是 UTC，脚本已处理换算）
- 会话「最后活跃时间」取 `state.json` 的 `updatedAt` 与会话文件 mtime 的较大者，避免 resumed 会话时间不准
- 标题为 "New Session" 的说明基本没聊内容，汇报时标注出来
