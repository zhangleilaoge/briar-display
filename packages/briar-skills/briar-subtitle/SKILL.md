# briar-subtitle — 视频字幕提取

把本地视频文件中的字幕或语音内容提取为文字，输出带时间轴的版本和纯文本版本。

## 触发场景

- 用户给一个本地视频文件（mp4/mov 等），要求"扒字幕"、"提取字幕"、"把视频里说的话整理成文字"

## 方式选择（先判断，再执行）

| 场景 | 方式 | 理由 |
|------|------|------|
| 视频有独立字幕流，且需要其中内容 | **直接导出字幕流** | 保留原始文本和时间轴，无需识别 |
| 需要提取讲述、对话等语音内容，且视频有音轨 | **transcribe 语音转录** | 直接得到完整语音文本，与视频题材和时长无关 |
| 需要画面中的可见文字，或视频无音轨 | **frames 抽帧直读** | 直接读取画面字幕，不依赖语音识别 |
| 语音转录失败，或个别词句需要结合画面字幕核对 | **frames 局部抽帧校对** | 只读取有疑问的时间点，不全片抽帧 |

先明确目标是“语音内容”还是“画面文字”，再看视频条件，不要按题材或视频时长套用固定流程。需要语音内容时，即使画面带有烧录字幕，通常也直接 transcribe；需要画面原字或语音转录不可靠时再用 frames。拿不准时先 probe 检查字幕流和音轨。

提取完成后直接交付文本或进行用户要求的后续处理；目标只是语音内容时，不要额外逐帧读图。

## 工作流

### Step 1 — 探测视频

```bash
bash video-subtitle.sh probe <video>
```

输出时长、音轨/字幕流信息。若视频内嵌独立字幕流（mov_text/subrip），直接 `ffmpeg -i <video> -map 0:s:0 out.srt` 导出即可，无需转录。

### Step 2a — 语音转录（提取语音内容）

```bash
bash video-subtitle.sh transcribe <video> [model]
# 默认模型 mlx-community/whisper-large-v3-turbo，语言中文
```

脚本自动准备环境（`~/.venvs/whisper` 隔离 venv + ffmpeg），输出带时间轴分段并保存 JSON 到 `/tmp/<视频名>_transcript.json`。模型首次下载时用后台任务运行，但等待期间不要默认抽帧代替转录。

### Step 2b — 抽帧直读（提取画面文字）

```bash
bash video-subtitle.sh frames <video> [fps] [outdir]
# 默认 1fps，输出到 /tmp/subtitle-frames-<视频名>/
```

需要提取画面文字或视频无音轨时，用 ReadMediaFile 逐批读帧图（每次 4-6 张），按文件名序号对应秒数整理出带时间轴的字幕，注意去除相邻帧的重复内容。帧数过多（>120）时降低抽帧频率或裁剪字幕区域再读。仅为校对个别词句时，按转录时间轴抽取对应帧，不做全片抽帧和拼图。

### Step 3 — 校对与交付

whisper 输出常有同音错别字（如“下雨”→“下游”、“发备”→“翻倍”），结合上下文修正后再交付，无法确认的修正不要当作原话。区分原始识别文本与人工整理内容，避免把压缩、润色后的句子当成逐字原文。

## 已知坑

- 本机无系统 ffmpeg：脚本用 `imageio-ffmpeg` pip 包自带的二进制，但其文件名不是 `ffmpeg`，mlx_whisper 按 `ffmpeg` 命令名调用会报 FileNotFoundError——脚本已自动做 symlink（`~/.venvs/whisper/ffmpeg-bin/ffmpeg`）并注入 PATH，不要绕过脚本直接调 mlx_whisper。
- 模型首次下载需几分钟（HF 未登录有限速），用后台任务跑，不要阻塞等待。
- 不要用系统 Python 3.9 装 whisper 生态，统一用脚本里的 uv 隔离 venv。
